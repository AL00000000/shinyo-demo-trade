## 実装済み

- 建玉ごとに銘柄コード・買建/売建・株数・建値・建日を手入力。英字コード、同一銘柄の複数建玉に対応。
- 現金保証金・諸経費・受渡未到来の決済損益を手入力。
- 代用株の銘柄・株数を登録。掛目は一律80%で固定し、入力欄はありません。旧登録や復元したデータも80%に統一します。
- 登録銘柄の終値で評価し、建玉別損益、通算、差引評価損、代用評価額、実質保証金、維持率の途中式を表示。
- 全銘柄の終値データをサーバーで取得して日付ごとに保存。欠落・日付混在・古い取得を拒否し、前回取得値を保持。
- 一律価格変化と入出金のシミュレーション。
- 株式分割などの権利処理が入力確認日より新しければ計算保留。
- 入力は端末内保存。JSONの書き出し・復元・削除。
- iOS・Android向けEAS Build設定。

## 終値サーバー

1. `.env.example`のサーバー設定を環境変数へ設定。`.env`を使う場合はNodeの`--env-file=.env`で読み込ませます。`tsx`だけでは自動読込しません。
2. 常時稼働サーバーへ配置し、`npm install`後、`node --env-file=.env --import tsx server/index.ts`を起動。
3. リバースプロキシでHTTPS化。公開アプリへ`EXPO_PUBLIC_API_URL`をビルド時に設定するか、設定画面でHTTPS URLを指定。
4. `API_ACCESS_TOKEN`に32文字以上のランダムキーを設定。`GET /health`と`GET /v1/snapshot`はどちらもAuthorization: Bearerによる認証が必要です。端末の設定画面でキーを入力します。保存を選ばない場合は再起動時に再入力が必要です。保存を選ぶと、iOS/AndroidではSecureStore、Webではブラウザ内にキーを保存します。バックアップにはキーを含めません。

サーバー起動時と18〜23時JSTの15分間隔で取得します。18時は仮の開始時刻です。契約先の配信時刻に合わせて調整してください。休場日・臨時休場・営業日判定は配信元のカレンダーを使用します。配信元は休日にも新しい`generatedAt`と直近の営業日を返す必要があります。遅延日は同日夜間に再試行し、次回起動でも追取得します。

一回だけ取得する場合:

```sh
node --env-file=.env --import tsx server/sync.ts
```

このPCにはWindowsタスク `\StockAutomation\ShinyoDemoPersonalServer` を登録済みです。ログオン時と毎日18時に `start-personal-server.ps1` が起動し、既存プロセスがある場合は重複起動しません。PCの起動・ネット接続が必要です。本人用では内閣府の祝日と週末・年末年始を除外します。臨時休場は自動判定していません。

アプリが終了している間もサーバーは終値を取得します。端末の画面は起動・復帰・利用中15分ごとの通信で最新終値に追いつきます。閉じたアプリを毎日必ず起動する仕組みやプッシュ通知は実装していません。

## 正規化データの契約

`src/schema.ts`が正規仕様です。例:

```json
{
  "version": 1,
  "source": "契約先のデータ名",
  "tradingDate": "2026-10-09",
  "expectedTradingDate": "2026-10-09",
  "generatedAt": "2026-10-10T09:00:00.000Z",
  "complete": true,
  "licensedForRedistribution": true,
  "markets": ["TSE", "NSE", "FSE", "SSE"],
  "expectedCount": 1,
  "quotes": [
    {
      "code": "7203", "market": "TSE", "name": "トヨタ自動車",
      "date": "2026-10-09", "close": "2500", "finalQuote": null,
      "status": "traded", "actionDate": null
    }
  ]
}
```

上記は項目の例です。全市場を宣言して1件だけ返すと市場欠落として拒否します。実際には市場ごとに全上場銘柄を列挙し、銘柄マスターとの照合件数を`expectedCount`へ入れます。価格のない銘柄も`no-price`で列挙してください。「全日本株」の市場範囲は東証・名証・福証・札証を初期設定としており、配信契約が全市場を網羅することを確認してください。ETF/REIT等の収録範囲も契約先銘柄マスターに従います。

- `close`: 当日の未調整終値。調整後終値を混ぜない。
- `finalQuote`: 気配引け時の最終気配値。通常約定引けではnull。
- `status`: `traded` / `quote-only` / `no-price`。
- `actionDate`: 直近の分割・併合など、入力値の確認が必要になった日付。アダプターで履歴を追跡する。
- `expectedTradingDate`: 配信元カレンダーで判定した対象営業日。株価レコードから逆算しない。
- `generatedAt`: 配信元の全市場確認完了時刻。通信しただけで現在時刻へ書き換えない。
- `licensedForRedistribution`: 真偽値は契約の代わりにはなりません。契約担当者が配信権を確認したうえでサーバー環境変数`DATA_LICENSE_CONFIRMED=true`を設定。

## ストア向けビルド・申請

Expo公式の手順に従ってEASを利用します。これはサイトをアプリ内WebViewで包む構成ではなく、React Nativeで画面を作るiOS/Androidアプリです。

1. `app.config.ts`の`jp.example.shinyodemotrade`をご自身の固有のBundle ID / Package名に置換。アプリ名を決定。
2. アプリアイコンとAndroid Adaptive Iconは作成済み。ストア用画像と必要に応じてスプラッシュを準備。
3. 株価契約、本番サーバー、公開HTTPS APIを用意。
4. Expoアカウント・Apple Developer・Google Play Consoleを用意。
5. `npx eas-cli login` → `npx eas-cli build:configure`。EAS projectIdはアカウント作成後に設定。
6. `npx eas-cli build --platform all --profile production`で署名済みiOS/Androidビルド。AndroidはAAB。
7. TestFlight / Google Play内部テストで実機確認。バックアップ・通信失敗・端末再起動・価格更新・日付・入力桁数を確認。
8. 運営者名・問い合わせ先・公開プライバシーポリシーURL・データ提供元表記・スクリーンショット・年齢区分・App Privacy / Data Safetyを記入し申請。

`eas.json`にビルド構成は用意済みです。申請前にAPI接続・実機・配信契約と運営者情報を確定する必要があります。ソースが書き出せることと、ストア審査に通ることは別です。

## v1.4 本人用の無料運用

このPCの`.env`に`PRICE_PROVIDER=public-personal`を設定し、`start-personal-server.ps1`で起動します。`server/run-personal.ts`がAPIとCloudflare Quick Tunnelを維持し、接続先が変わったらGitHub Pagesの`api-endpoint.json`を更新します。価格やキーをGitHubへ送信しません。無料の一時接続には稼働保証がなく、このPCが停止・スリープ中なら通信できません。

このPCにはWindowsタスク `\StockAutomation\ShinyoDemoPersonalServer` を登録しました。ログオン時と毎日18:00に起動を確認します。スリープからの復帰と取りこぼしの後追いを有効化しています。サーバーが起動していれば18〜23時の15分間隔で日次取得・再試行します。初回の全件取得は時間がかかるため途中の取得状況を配信します。入力した銘柄が未取得なら率は表示しません。

対象営業日は内閣府の祝日CSV・土日・取引所の年末年始休場から判定します。臨時の市場停止には別途対応が必要です。対象営業日の`close`だけを使い、`adjclose`や場中の`regularMarketPrice`は使いません。分割イベントを確認し、確認日前の変更があれば株数・建値の見直しを促します。

このPCでは、既存の本人用Yahoo取得キャッシュが同じ営業日の場合だけ再利用します。既存キャッシュに権利処理履歴がない場合は、その営業日まで入力を確認していない建玉の計算を保留します。端末の確認日を勝手に進めません。

無料取得のデータに`licensedForRedistribution=true`は付けません。`usage=personal`として一般配信契約と区別します。これは取得元の利用許諾を保証するものではありません。取得元の仕様変更・利用制限で停止する可能性があります。第三者向け配信や商用運用はこの構成の対象外です。
初回のスマートフォン接続は、本人用QRを読み取るとキーが入力されます。キーはURLのフラグメントで渡し、HTTPリクエストには含めず、読み取り後にブラウザ履歴のURLから除きます。QR・本人用URL・キーのファイルは公開しません。次回も自動接続するには、設定の『この端末に接続キーを保存』を本人が選んでください。

v1.5.3の銘柄タブは掛目・代用評価額を省き、評価価格の対象日、信用建玉と現物それぞれの含み損益、現物＋信用の合計を表示します。現物の購入単価は編集から入力してください。旧登録で購入単価がなければ損益は未算出です。損益は税金・費用控除前、現物は掛目前の時価で算出し、信用維持率とは別の表示です。
